## 2. 本地构建

### 控制台 UI（React）

```powershell
cd llm-gateway/ui
pnpm install          # 首次
pnpm dev              # 开发：vite dev server，/api 与 /static 代理到 127.0.0.1:8001
pnpm build            # 产物写入 llm-gateway/static/（index.html + assets/）
```

`static/` 产物**随仓库提交**：干净 clone 上 `cargo build` 无需 Node。改了 `ui/` 源码后必须
`pnpm build` 并把 `static/` 的变更一起提交（hash 文件名变化属正常）。
`static/fonts/` 与 `static/sakura-fonts.css` 是手写维护的，构建不会触碰。

> 构建全部在本地完成（不走 GitHub Actions）；`.github/workflows/release.yml` 仍是旧单文件 UI 时代的产物，仅供参考。

### Windows 可执行文件

```powershell
cd llm-gateway
cargo build --release        # 产物：target/release/llm-gateway.exe（内嵌 static/）
```

**关键坑（rust-embed 不追踪静态文件）**：只改 `static/` 内容时，必须 touch 一个 .rs 文件（惯例 touch `src/ui.rs`）再 build，否则二进制里嵌的还是旧 UI。Windows exe 和 Android 交叉编译都受此影响。

构建前杀掉运行中的实例，否则链接器报 os error 5：

```powershell
Get-Process llm-gateway,mock_upstream -ErrorAction SilentlyContinue | Stop-Process -Force
```

### Android APK

```powershell
.\android\build-local.ps1            # 构建 release APK
.\android\build-local.ps1 -Install   # 构建 + adb 安装到已连接设备
```

## 3. 核心设计不变量（改动时不得违反）

这些是用多次线上事故换来的，详见 `PASS.md`：

1. **容量真相只来自配置**。每 Key 容量 = seed_rpm > 提供商 rpm_limit/tpm_limit 按 Key 数拆分。**不要**从 429 采样反推容量——429 的「rpm 或 tpm 任一触发」语义证明采样无法区分二者，历史上这么做过三次，每次都把利用率钉死在 100%。

2. **冷却链**：Retry-After 头 → 每 Key cooldown_secs 覆盖 → 60s 窗口推算（用量老化排空 ×0.9 偏低取，钳制 [2,900]s）→ 全局默认。探测器（prober）**已整体移除且不得复活**——它本身消耗 RPM 额度，且「二分探测失败时写入编造的 learned_cooldown」曾导致第二天整池瘫痪。

3. **零失败 hold**：全冷却时挂起等待最近恢复的 Key（上限 `max_hold_secs`，默认 120s），无尝试计数器——hold 预算严格消耗、就绪集严格缩小，天然终止。

4. **比较器顺序**：有效优先 → 非冷却优先 → 用户排序栈 → idx 游标轮转。排序键 K = 平滑成功率 × headroom。

5. **配额耗尽的 429**（"entitlement exhausted"、"insufficient_quota"、"余额不足" 等 body 标记）→ `mark_invalid` 30 分钟，不是短冷却。

6. **统计合并进 gateway.json**（stats 字段），不落第二个文件；导入配置时统计被采纳而非丢弃。

## 4. 控制台 UI 约定

- React 18 + TypeScript（`llm-gateway/ui/`），构建产物嵌入二进制；没有独立前端服务。
- 提交前 `pnpm -C llm-gateway/ui build`（内含 `tsc --noEmit` 类型检查门禁）。
- 轮询：API Key 页和统计页 1s（`store.tsx` 的 interval）。统计页是 change-detected 渲染（payload 字节不变不 setState）；React 调和保留 DOM 节点，主区 scrollTop、直方图 scrollLeft、输入焦点天然不丢——不要改回 innerHTML 式全量替换。
- Key 冷却倒计时由 `data.now` 1s tick 派生（`untilMs - now`），到 0 触发一次去抖的 refreshAkStatus。
- 中英双语文案走 `i18n.ts` 的 `t()`/`tp()`；新增文案两个语言都要加。
- Android 专属能力通过 `window.SakuraAndroid` JS 桥（电池优化/自启动跳转、横屏锁定、状态栏主题），UI 里用 `window.SakuraAndroid ? ... : null` 门控。

### 主题系统

- 主题 = `themes/<id>/` 目录：`theme.json`（name/author/version/description/`mode: light|dark`/`css[]`/`js[]`/`preview`）+ 其引用的 CSS/JS/图片。`id` 就是目录名（theme.json 里不写 id）。
- 内置主题 `static/themes/sakura-light`、`sakura-dark` 嵌进二进制；配置文件旁的 `themes/` 目录里同名 id **覆盖**内置（用户魔改默认主题的路径：复制一份到外部再改）。
- 接口：`GET /api/themes`（清单 + 当前 id）、`GET /themes/{id}/{path}`（主题文件，外部优先；拒绝 `..` 穿越）。主题选择存在 `gateway.json` 的 `theme` 字段（`PUT /api/settings` 带上，缺省 `sakura-dark`）。
- **分层加载**：主题的 `mode` 对应的基底主题（sakura-light/dark）永远垫在下面，主题自己的 css 盖在上面——所以部分覆盖（只改几个 token）的主题也能正常渲染；完整主题把 token 全覆盖即可。
- 前端：`ui/src/theme.ts` 负责注入/移除 `<link data-theme-css>` 和 `<script data-theme-js>`；`ui/index.html` 里的启动注入器用 localStorage 缓存的 manifest 在首帧前应用主题（不闪）。顶栏亮暗按钮 = 在最近用的亮色/暗色主题间快切（`sakura-last-light/dark`）。
- 写新主题的最快路径：复制 `static/themes/sakura-dark/` 到配置旁的 `themes/my-theme/`，改 theme.json 的 name，再改 theme.css 里的 token。
- 安全注意：主题的 js 在控制台里拥有完全权限（能读所有 Key），只装自己信任的主题。

## 5. 测试

```powershell
cd llm-gateway
cargo test                                    # 单元测试
cargo run --bin mock_upstream                 # 假上游：127.0.0.1:9001
```

mock_upstream 的 Key 约定：`sk-bad` 恒 429（Retry-After: 2）、`sk-dead` 恒 401、`sk-slow` 慢响应、`sk-window-<N>` 模拟每 Key 窗口、`sk-poor` 配额耗尽。配合 `test/gateway.json`（gitignored，自建）做端到端验证。

| 接口 | 方法 | 说明 |

| `/api/status` | GET | 实时配置 + Key 池状态 + 版本号 |
