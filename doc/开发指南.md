## 2. 本地构建

### 控制台 UI（React）

```powershell
cd llm-gateway/ui
pnpm install          # 首次
pnpm dev              # 开发：vite dev server，/api 与 /static 代理到 127.0.0.1:8001
pnpm build            # 产物写入 llm-gateway/static/（index.html + assets/）
```

`static/` 产物**随仓库提交**：干净 clone 上 `cargo build` 无需 Node。改了 `ui/` 源码后必须
`pnpm build` 并把 `static/` 的变更一起提交（hash 文件名变化属正常）。
`static/fonts/` 与 `static/sakura-fonts.css` 是手写维护的，构建不会触碰。

> 构建全部在本地完成（不走 GitHub Actions）；`.github/workflows/release.yml` 仍是旧单文件 UI 时代的产物，仅供参考。

### Windows 可执行文件

```powershell
cd llm-gateway
cargo build --release        # 产物：target/release/llm-gateway.exe（内嵌 static/）
```

**关键坑（rust-embed 不追踪静态文件）**：只改 `static/` 内容时，必须 touch 一个 .rs 文件（惯例 touch `src/ui.rs`）再 build，否则二进制里嵌的还是旧 UI。Windows exe 和 Android 交叉编译都受此影响。

构建前杀掉运行中的实例，否则链接器报 os error 5：

```powershell
Get-Process llm-gateway,mock_upstream -ErrorAction SilentlyContinue | Stop-Process -Force
```

### Android APK

```powershell
.\android\build-local.ps1            # 构建 release APK
.\android\build-local.ps1 -Install   # 构建 + adb 安装到已连接设备
```

## 3. 核心设计不变量（改动时不得违反）

这些是用多次线上事故换来的，详见 `PASS.md`：

1. **容量真相只来自配置**。每 Key 容量 = seed_rpm > 提供商 rpm_limit/tpm_limit 按 Key 数拆分。**不要**从 429 采样反推容量——429 的「rpm 或 tpm 任一触发」语义证明采样无法区分二者，历史上这么做过三次，每次都把利用率钉死在 100%。

2. **冷却链**：Retry-After 头 → 每 Key cooldown_secs 覆盖 → 60s 窗口推算（用量老化排空 ×0.9 偏低取，钳制 [2,900]s）→ 全局默认。探测器（prober）**已整体移除且不得复活**——它本身消耗 RPM 额度，且「二分探测失败时写入编造的 learned_cooldown」曾导致第二天整池瘫痪。

3. **零失败 hold**：全冷却时挂起等待最近恢复的 Key（上限 `max_hold_secs`，默认 120s），无尝试计数器——hold 预算严格消耗、就绪集严格缩小，天然终止。

4. **比较器顺序**：有效优先 → 非冷却优先 → 用户排序栈 → idx 游标轮转。排序键 K = 平滑成功率 × headroom。

5. **429 / 401 的分级处理**（`proxy.rs`）：只有 **401/403 进异常**（`AUTH_INVALID_SECS` = 1 小时，比原来的 30 分钟久）；**配额耗尽**（body 说 plan/entitlement 用尽，如 `token plan entitlement exhausted`）→ **冷却 5 小时**（`QUOTA_COOLDOWN_SECS`），不进异常——配额是容量状态不是异常。**限流信号优先于配额标记**：body 里出现 `tpm/rpm` / `inference exceeds` / `rate_limit_error` 就是普通冷却，即使 code 写着 `insufficient_quota`（商汤真实响应就是这么塞的，曾经因此把整池 15 把健康 Key 全塞进 5 小时冷却）。

6. **统计合并进 gateway.json**（stats 字段），不落第二个文件；导入配置时统计被采纳而非丢弃。

7. **落盘必须「写临时文件 → fsync → rename」**（`config::write_atomic`）。少了 fsync，NTFS 可以先提交 rename（大小、目录项）而数据块还脏在页缓存里；断电/硬杀之后留下一个**长度正确、内容全是 0x00** 的文件——线上出现过两个 23 KB 的 `gateway.json` 全零，正是这个成因。每一次 rename 前还顺手把上一份仍能解析的文件复制成 `gateway.json.bak`（最多每分钟一次，避开每 5 秒的热路径）。

8. **加载失败要能自愈，且必须报对原因**：`gateway.json` 读不出来时先尝试 `.bak`（还原时原样拷贝备份字节，不重新序列化——否则 `stats` 块里的历史 token 计数会被清零）；没有备份才报错，并且**区分「读不出来（UNREADABLE）」和「写不下去（NOT WRITABLE）」**——把损坏的配置报成权限问题，会把人送去查 ACL（真的发生过）。

## 4. 控制台 UI 约定

- React 18 + TypeScript（`llm-gateway/ui/`），构建产物嵌入二进制；没有独立前端服务。
- 提交前 `pnpm -C llm-gateway/ui build`（内含 `tsc --noEmit` 类型检查门禁）。
- 轮询：API Key 页和统计页 1s（`store.tsx` 的 interval）。统计页是 change-detected 渲染（payload 字节不变不 setState）；React 调和保留 DOM 节点，主区 scrollTop、直方图 scrollLeft、输入焦点天然不丢——不要改回 innerHTML 式全量替换。
- Key 冷却倒计时由 `data.now` 1s tick 派生（`untilMs - now`），到 0 触发一次去抖的 refreshAkStatus。
- 中英双语文案走 `i18n.ts` 的 `t()`/`tp()`；新增文案两个语言都要加。
- Android 专属能力通过 `window.SakuraAndroid` JS 桥（电池优化/自启动跳转、横屏锁定、状态栏主题），UI 里用 `window.SakuraAndroid ? ... : null` 门控。

### 主题系统

- 主题 = `themes/<id>/` 目录：`theme.json`（name/author/version/description/`mode: light|dark`/`css[]`/`js[]`/`preview`）+ 其引用的 CSS/JS/图片。`id` 就是目录名（theme.json 里不写 id）。
- 内置主题（编译期内嵌）：`sakura-dark` / `sakura-light`（默认两档）、`github-dark`（Primer dark dimmed）、`dracula`（官方暗紫）、`glass`（毛玻璃，带 `theme.js` 视差）、`anime`（二次元浅色，带 `theme.js` 樱花飘落）。配置文件旁的 `themes/` 目录里同名 id **覆盖**内置（用户魔改默认主题的路径：复制一份到外部再改）。
- 接口：`GET /api/themes`（清单 + 当前 id）、`GET /themes/{id}/{path}`（主题文件，外部优先；拒绝 `..` 穿越）。主题选择存在 `gateway.json` 的 `theme` 字段（`PUT /api/settings` 带上，缺省 `sakura-dark`）。
- **分层加载**：主题的 `mode` 对应的基底主题（sakura-light/dark）永远垫在下面，主题自己的 css 盖在上面——所以部分覆盖（只改几个 token）的主题也能正常渲染；完整主题把 token 全覆盖即可。
- 前端：`ui/src/theme.ts` 负责注入/移除 `<link data-theme-css>` 和 `<script data-theme-js>`；`ui/index.html` 里的启动注入器用 localStorage 缓存的 manifest 在首帧前应用主题（不闪）。顶栏亮暗按钮 = 在最近用的亮色/暗色主题间快切（`sakura-last-light/dark`）。
- 写新主题的最快路径：复制 `static/themes/sakura-dark/` 到配置旁的 `themes/my-theme/`，改 theme.json 的 name，再改 theme.css 里的 token。
- 主题作者约定（新增主题请遵守）：① token 需覆盖 `static/themes/sakura-dark/theme.css`（亮色主题对应 `sakura-light`）里的**全部** `--color-*`/`--font-*`/`--shadow-*`，否则会漏出默认粉调；② 正文/次级/三级文字对各自实际背景需 ≥ WCAG AA 4.5:1，主按钮文字对 base/hover/active **三态**都要过；③ 禁止 `@import` 与任何远程字体/图片——控制台要能离线跑；④ 装饰层一律 `position:fixed; pointer-events:none`，不得改 `.app`/`.main`/`.card` 的 position/display/宽高，也不要给 `body` 加 overflow；⑤ 主题 js 若创建动画，必须清理上一实例（挂 `window.__sakuraXxxFx`）并能检测自己被移出 DOM 后停止，`prefers-reduced-motion: reduce` 时不做动画。
- 安全注意：主题的 js 在控制台里拥有完全权限（能读所有 Key），只装自己信任的主题。

## 5. 测试

```powershell
cd llm-gateway
cargo test                                    # 单元测试
cargo run --bin mock_upstream                 # 假上游：127.0.0.1:9001
```

**沙箱里跑测试要先改 TEMP**：有几条测试用 `std::env::temp_dir()` 建配置目录，在 DSH/受限环境里该路径不可写会报 `PermissionDenied`（看起来像 6 条"预置失败"，其实是环境问题）。指向工作区即可全绿：

```powershell
$env:TEMP="L:\sakura-dev\.tmp"; $env:TMP=$env:TEMP; New-Item -ItemType Directory -Force $env:TEMP
cargo test
```

mock_upstream 的 Key 约定：`sk-bad` 恒 429（Retry-After: 2）、`sk-dead` 恒 401、`sk-slow` 慢响应、`sk-window-<N>` 模拟每 Key 窗口、`sk-poor` 配额耗尽、`sk-split` 把 usage 事件拆成两个 chunk 发出（验证跨 chunk 解析）。配合 `test/gateway.json`（gitignored，自建）做端到端验证。

### 排障：exe「拒绝访问」且改权限无效

如果从自动化/沙箱进程复制出来的 exe 一运行就报 `拒绝访问 (os error 5)`，**连 `%LOCALAPPDATA%` 也写不进去**，那不是 ACL 问题，而是文件带了 **Low 完整性标签**——用它启动的进程继承 Low 完整性，写不了任何普通（中完整性）目录。`icacls` 能看到：

```
Mandatory Label\Low Mandatory Level:(I)(NW)
```

修复（把标签提回 Medium，无需管理员以外的特殊操作）：

```powershell
icacls "路径\llm-gateway.exe" /setintegritylevel Medium
```

判断依据：同目录下你自己（普通进程）能创建文件，但该 exe 不能 → 就是这个标签。

**构建目录也会被污染**。如果 `target\` 是低完整性进程（早期沙箱构建）创建的，里面所有新产物都会继承 Low 标签：`cargo test` 报 `PermissionDenied`（即使 `TEMP` 已改好），`cargo build` 出来的 exe 一部署就是「写不进配置」。一次性把继承标签提回来：

```powershell
icacls "llm-gateway\target" /setintegritylevel "(OI)(CI)Medium"
```

之后新产物自动继承 Medium；已存在的旧产物按需对单个文件执行 `/setintegritylevel Medium`。

### 排障：启动横幅里的配置状态

```
[gateway] config file: <路径>                                        # 正常
[gateway] config file: <路径> (UNREADABLE — built-in defaults in memory)   # 文件在，但读不出来
[gateway] config file: <路径> (NOT WRITABLE — built-in defaults in memory) # 目录不允许创建
```

`UNREADABLE` 的典型原因是上面那两种：全 NUL（硬杀/断电/复制中断）或 JSON 写坏（编辑时多了逗号）。此时启动日志会给出具体字节数，并在存在 `gateway.json.bak` 时**自动还原**。两者都会退回内置默认配置继续跑，但**新增的 Key/设置只存在内存里**，退出即丢——所以别在这个状态下添加 Key。
