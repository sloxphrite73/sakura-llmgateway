# Sakura LLM Gateway — 使用说明

一个本地 LLM API 网关，位于你的 agent/工具与上游 OpenAI 兼容提供商之间。
它为每个提供商维护一个 API-Key 池，在某个 Key 被限流时自动切换到下一个，
并提供 Web 控制台管理一切。

> English: [USAGE.md](USAGE.md)

---

## 1. 安装与启动

### 一键脚本（推荐）

| 平台 | 步骤 |
|---|---|
| Windows | 先双击一次 `llm-gateway/install.bat`（自动安装 Rust、下载 MinGW、构建 release、生成 `gateway.json`）。之后每天用 `llm-gateway/start.bat` 启动即可。 |
| Linux / macOS / Git Bash | 先 `./install.sh` 一次，之后 `./start.sh`。 |

注意：

- `start.bat` / `start.sh` 是**前台运行**——使用期间窗口必须保持打开，关窗即停止网关。
- 如果 release 二进制已存在，启动脚本会跳过构建直接运行。

### 手动方式

```bash
cd llm-gateway
cargo build --release
./target/release/llm-gateway.exe --config gateway.json   # Windows
./target/release/llm-gateway --config gateway.json       # Linux/macOS
```

启动后：

| 服务 | 地址 |
|---|---|
| OpenAI 兼容 API | `http://127.0.0.1:8000/v1` |
| Web 控制台 | `http://127.0.0.1:8001/` |

## 2. Web 控制台

浏览器打开 `http://127.0.0.1:8001/`，从上到下：

### 全局设置

- **默认冷却时间（秒）**——上游没有返回 `Retry-After` 且 Key 没有单独覆盖时，429 的 Key 休息多久（默认 60）。
- **每请求最大尝试次数**——重试预算倍数（默认 3）。实际预算 = `max_attempts × Key 数量`，所以只有所有可用 Key 都试过之后，请求才会失败。
- **API 端口 / UI 端口**——重启后生效。
- **本地 API 鉴权**——默认关闭。开启后 agent 访问 `/v1/*` 必须携带配置的鉴权 Key 作为 Bearer token。

### 提供商

每个提供商卡片管理一个上游：

- **编辑 / 删除**提供商（名称 + baseURL）。
- **API Key**——添加/删除 Key、可选的每 Key 冷却时间覆盖、实时状态、请求数、最近错误。Key 值始终掩码显示。
- **模型**——托管模型目录（见第 4 节）。
- **别名**——映射到上游模型名的短名称（见第 5 节）。

**Key 状态含义：**

| 状态 | 含义 |
|---|---|
| 🟢 可用 | 健康，参与轮询 |
| 🟡 冷却 · 剩余 Xs | 暂时停用（429 或 5xx），倒计时到 0s 自动恢复 |
| 🔴 无效 · 剩余 Xs | 鉴权被拒（401/403）——重试不可能成功，因此隔离 30 分钟。修复 Key 后点**解除无效**立即恢复 |

### 主题

页头右侧的 ☀️/🌙 按钮切换浅色/深色模式。选择按浏览器记忆（localStorage），默认深色。

## 3. Key 池行为（429 时发生了什么）

1. 请求按轮询方式分配到提供商的各个 Key。
2. 收到 **429** 的 Key 进入冷却：冷却时长优先级 = 上游 `Retry-After` 头 → 每 Key 覆盖 → 全局默认。网关等待 **1.5 秒**后在下一个 Key 上重试同一请求。
3. **401/403**（Key 无效）改为 30 分钟隔离——反复重试死 Key 只是浪费调用。
4. 其他 Key 级错误（408/5xx、网络错误）让 Key 停用 5 秒后轮换。
5. 请求级错误（如 **400** 坏请求体）直接返回客户端——换什么 Key 结果都一样。
6. 只有当**所有** Key 都在冷却/无效时，客户端才会收到 `429`（附停用 Key 列表，快速失败不等待）。
7. 响应首字节转发后，流原样透传——不会在流中途切换 Key（那会损坏输出）。
8. Agent 对话中的每次失败请求就是一次普通的 `/v1/chat/completions` 调用：一个客户端请求 → 每次尝试用一个 Key。

## 4. 模型管理

每个提供商的**模型**区块管理一个模型目录，每个条目为 `{ id, enabled }`：

- **手动添加**——输入上游模型 ID（如 `gpt-4o`）。
- **从上游拉取**——调用提供商的实时 `/v1/models`，弹出勾选列表（已添加的模型不勾选），选择后导入。
- **启用/禁用**——不删除即可临时下线某个模型（比如配额耗尽）。
- **白名单模式**（仅允许列表内模型，默认关）：
  - 关 + 列表为空 → 未托管，所有模型放行（向后兼容）；
  - 开 → 只允许请求列表内已启用的模型，其余返回明确的 404。
- 被禁用的模型和悬空别名不会出现在 `/v1/models` 中。

---

## 5. 模型命名与别名

Agent 请求模型的方式：

- **复合名：**`provider/model`——如 `openai/gpt-4o`（`provider` 匹配提供商的名称或 ID）。
- **别名：**你定义的任意短名，如 `fast` → `gpt-4o-mini`。别名优先于复合名，跨提供商全局唯一。

`GET /v1/models` 列出所有已启用的托管模型（`provider/model` 格式）及全部有效别名。

## 6. 接入 Agent 与工具

任何支持 OpenAI 接口的客户端都能用：

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="anything")
```

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-4o","messages":[{"role":"user","content":"hi"}],"stream":true}'
```

如果开启了本地 API 鉴权，`api_key` 填网关的某个鉴权 Key（Bearer token）。

流式（SSE）与非流式响应均支持，逐字节透传。

## 7. 配置文件参考（`gateway.json`）

```json
{
  "api_port": 8000,
  "ui_port": 8001,
  "default_cooldown_secs": 60,
  "max_attempts": 3,
  "auth": { "enabled": false, "keys": [] },
  "providers": [
    {
      "id": "p-xxx",
      "name": "openai",
      "base_url": "https://api.openai.com/v1",
      "keys": [
        { "id": "k-xxx", "key": "sk-...", "label": "main", "cooldown_secs": null }
      ],
      "models": [ { "id": "gpt-4o", "enabled": true } ],
      "model_allowlist_only": false,
      "aliases": { "fast": "gpt-4o-mini" }
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `api_port` / `ui_port` | 本地 API 与控制台端口（重启生效） |
| `default_cooldown_secs` | 无 `Retry-After` 且无每 Key 覆盖时的 429 冷却时长 |
| `max_attempts` | 重试预算倍数（实际预算 = × Key 数量） |
| `auth` | 本地 `/v1` API 的可选 Bearer 鉴权 |
| `keys[].cooldown_secs` | 每 Key 冷却覆盖；`null` = 用全局默认 |
| `models` | 托管目录；为空 = 未托管 |
| `model_allowlist_only` | 拒绝不在（非空）列表内的模型 |
| `aliases` | 客户端可见名称 → 上游模型名 |

每次在控制台修改都会原子重写该文件。网关运行时手动编辑也可以——但控制台的修改会覆盖手动修改。

> **警告：** 某些工作副本中的 `llm-gateway/test/gateway.json` 含有本地测试用真实 API Key——切勿提交或外传。

## 9. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 明明有 Key 可用，客户端却收到 429 | 剩余 Key 全部在冷却/无效中；鼠标悬停 Key 状态看最近错误。修复或解除无效 Key。 |
| 某 Key 显示 无效 | 上游拒绝了鉴权（401/403）——Key 被吊销、写错或配额等级不足。修复后点解除无效。 |
| 真实请求不多，计数器却涨得快 | Agent 每次工具调用就是一次 API 请求，每次 429 重试也按次计数。401 隔离 + 429 退避（v0.2 加入）已把浪费压到最低，死 Key 现在每 30 分钟最多消耗 1 次调用。 |
| `cargo run` 询问运行哪个二进制 | 用 `cargo run --bin llm-gateway`，或直接运行编译产物 / 启动脚本。 |
| 端口被占用 | 已有网关实例在运行（Windows 用 `taskkill //F //IM llm-gateway.exe`），或修改 `api_port`/`ui_port`。 |
| 改了端口没生效 | 端口修改重启后生效。 |
| `.bat` 窗口一闪而过 | 重新下载修复后的脚本（纯 ASCII 版本）；在已打开的 cmd 窗口中运行可以看到报错。 |

## 10. 管理 REST API（控制台所用）

均在 `http://127.0.0.1:8001`：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/status` | 完整快照：设置 + 每提供商的 Key（掩码）及冷却/无效/请求数/最近错误 |
| `GET/POST /api/providers` | 列出 / 创建提供商 |
| `PUT/DELETE /api/providers/{id}` | 更新 / 删除提供商 |
| `POST /api/providers/{id}/keys` · `DELETE /api/providers/{id}/keys/{key_id}` | 添加 / 删除 Key |
| `DELETE /api/keys/{key_id}/cooldown` | 清除 Key 的冷却**或**无效隔离 |
| `POST /api/providers/{id}/models` · `DELETE .../models/{model_id}` · `PUT .../models/{model_id}` | 添加 / 删除 / 启停托管模型 |
| `GET /api/providers/{id}/upstream-models` | 拉取提供商实时 `/v1/models` |
| `POST /api/providers/{id}/models/import` | 批量导入 `{ "models": ["a", "b"] }` |
| `POST /api/providers/{id}/aliases` · `DELETE .../aliases/{alias}` | 设置 / 删除别名 |
| `PUT /api/settings` | 更新全局设置 |
