# Sakura LLM Gateway — 使用说明

本地 LLM API 网关：夹在你的 agent/工具与上游提供商之间，为每个提供商维护
API Key 池，限流自动轮换、全冷却时挂起等待，并提供 Web 控制台管理一切。

> English: [USAGE.md](USAGE.md)

---

## 1. 安装与启动

### 下载即用（推荐）

从 [GitHub Releases](https://github.com/sloxphrite73/sakura-llmgateway/releases)
下载 `sakura-llmgateway-vX.Y.Z-x86_64-pc-windows-msvc.exe`，放进一个空文件夹，
双击运行。首次启动会在同目录生成 `gateway.json`。

### 从源码构建

```bash
cd llm-gateway
cargo build --release
./target/release/llm-gateway.exe                        # 配置默认 ./gateway.json
./target/release/llm-gateway.exe --config path/to/gateway.json
```

启动后：

| 服务 | 地址 |
|---|---|
| OpenAI 兼容 API | `http://127.0.0.1:8000/v1` |
| Anthropic Messages API | `http://127.0.0.1:8000/v1/messages`（见第 5 节） |
| Web 控制台 | `http://127.0.0.1:8001/` |

> 一键脚本 `install.bat` / `start.bat` / `install.sh` / `start.sh` 仍可用
> （前台运行，窗口关则网关停）。

## 2. 安卓端（APK）

安卓版与 Windows 版是**同一个 Rust 网关**，交叉编译打包进 universal APK，
由前台服务启动并守护。UI 是同一个 Web 控制台的全屏 WebView。

### 安装与首次启动

1. 从 Releases 下载 `sakura-llmgateway-vX.Y.Z-universal.apk` 安装
   （允许"安装未知应用"）。
2. 首次启动可**导入 gateway.json**（从电脑导出）或**跳过用空配置启动**。

### 日常使用

| 事项 | 说明 |
|---|---|
| 前台服务 | 常驻通知（点通知回控制台，通知带"停止"按钮） |
| 保活 | 前台服务 + 10 秒看门狗（假死自动重启）+ START_STICKY + 开机自启（BootReceiver）。设置页底部「安卓后台保活」卡片（仅 app 内显示）一键跳转**免除电池优化**和**自启动设置**（小米/澎湃/OPPO/vivo 深链）。建议再在最近任务页长按本应用卡片选「锁定」。自启动权限只能手动授予 |
| 横屏 | 打开宽表单（添加提供商、模型/模型组编辑）时自动横屏；旋转屏幕后页面状态（当前页签、编辑中的表单草稿）自动恢复 |
| App 内导入 | 控制台"导入配置"调起系统文件选择器，导入即热生效 |
| 系统级导入 | 文件管理器中对 `gateway.json` 用"打开方式 → Sakura LLM Gateway"，运行中热加载 |
| 导出 | 控制台"导出配置"调起系统"另存为" |

### 从电脑迁移配置到手机

电脑控制台 → 设置 → **导出配置** → 把 `gateway.json` 传到手机 → 按上表任一方式导入。

## 3. Web 控制台

浏览器打开 `http://127.0.0.1:8001/`。六个页签：统计 · 提供商 · 模型 · 策略 ·
API Key · 设置；深/浅色 + 中/英文（localStorage 记忆）。手机上为底部标签栏布局。

### 设置页

- **默认冷却时间（秒）**——429 冷却链的兜底值（默认 60），见 §4.1。
- **每请求最大尝试次数**——遗留字段，保留兼容；重试现已由「全冷却最长等待」预算接管（见 §4）。
- **全冷却最长等待（秒）**——所有 Key 都在冷却时，请求最多挂起多久等最早恢复的 Key（默认 120）。
- **API 端口 / UI 端口**——重启后生效。
- **本地 API 鉴权**——开启后 `/v1/*` 需携带配置的鉴权 Key（Bearer token）。
- **导出 / 导入配置**——整份 `gateway.json`（含统计）下载；导入先验证后热切换，
  有任何错误整份拒绝，在途请求在旧状态上跑完。

### 提供商页

- 「+ 添加」：自定义添加，或从**免费目录**一键添加（25 家有免费额度的
  OpenAI 兼容上游，每张卡片带免费说明、预置模型、领额度教程与注册链接；
  可「从 GitHub 更新目录」拉取最新版）。
- 每个提供商卡片可编辑：名称、Base URL、协议（openai/anthropic）、RPM/TPM
  限额（可切"采用自动检测结果"，显示实测聚合值）。
- 删除提供商连带删除其全部 Key。

### 模型页

- 托管模型目录：手动添加 / 从上游 `/v1/models` 一键拉取勾选导入。
- 每模型可设：启停、上下文长度、输入/输出价格、图片输入开关、别名。
- **白名单模式**：开启后只放行列表内已启用模型，其余 404。
- **模型组**：声明同一逻辑模型跨提供商（如 `gpt-4o = {openai/gpt-4o, azure/gpt-4o}`），
  供策略层"模型优先"模式跨提供商 fallback。

### 策略页

- **两个过滤开关**：`lock_model_group` / `lock_provider`（默认都开 = 精确
  provider+model，只轮换 Key）。组合出四种候选模式：精确 / 模型优先 /
  提供商优先 / 可用优先（详见 §4.2）。
- **排序栈**：A–L 排序键，最多 3 个槽位。
- **Dry-run 预览**：选模型（+可选提供商）模拟一次路由，显示命中的 Key 与完整候选表。

### API Key 页

跨所有提供商的全局 Key 表，每秒轮询刷新（单元格补丁式更新，不打断操作）。

**添加 Key**：顶部选择提供商，文本框粘贴 Key——支持批量（每行一个），
且每行可带**显示名**：`名字 空格 Key`（名字可含空格，按最后一个空格切分）。
不填名字则以掩码形式（`sk-ab••••1234`）作为显示名。

表格列：**名字**（最左黏性列，超长省略号、悬停看全名）→ **Key**（掩码，
「显示」按钮查看全量）→ 提供商 → 智能冷却时长 → 状态 → RPM / TPM / 利用率
（悬停显示实测容量）→ avg_TFTT → token 余额 → 账单 → 请求数 → 最近错误 → 操作。

每行操作：**显示/隐藏**、**复制**、**编辑**、**删除**。

- **编辑**弹出「编辑Key信息」窗口：修改**显示名**（留空 = 回落掩码）和
  **Key 本体**（Key 的 id 不变，统计数据保留）。
- **状态含义**：🟢 可用 / 🟡 冷却·剩 Xs（429 或 5xx，倒计时自动恢复）/
  🔴 无效·剩 Xs（401/403 或配额耗尽，隔离 30 分钟，修复后点「解除」恢复）。
- **移动所有无效Key至回收站**：一键删除全部无效 Key。

### 统计页

- 总览卡片：成功/失败请求、换 Key 次数、成功率、**Token 总消耗**
  （≤1000 完整显示；超过按「x,xxxK」截断显示，悬停看完整值）。
- 过去 24 小时请求 / Token 用量柱状图（每小时一柱，窄屏可横滑，点柱子看该小时明细）。
- 按提供商 / 按模型 / 按 API Key 的明细表（Key 显示其显示名，改名即时生效）。

## 4. Key 池行为（429 时发生了什么）

1. 请求按策略层（§4.2）选中的 Key 发出。
2. 收到 **429** 的 Key 进入冷却，冷却时长按 §4.1 的链解析；网关**等待 250 毫秒**后
   用下一把 Key 重试同一请求。若 429 响应体表明**配额耗尽**（"entitlement
   exhausted" / "insufficient_quota" / "exceeded your current quota" /
   "余额不足" 等），这不是限流窗口——该 Key 按无效隔离 30 分钟，不再白撞。
3. **401/403**（Key 无效）同样 30 分钟隔离——反复重试死 Key 只是浪费调用。
4. 其他 Key 级错误（408/5xx、网络错误）让 Key 短暂冷却后轮换。
5. 请求级错误（如 **400** 坏请求体）直接返回客户端——换什么 Key 结果都一样。
6. **所有 Key 都在冷却时，请求挂起等待**最早恢复的 Key（客户端看到延迟而非失败）；
   累计等待超过「全冷却最长等待」（默认 120 秒）才返回 `429 + Retry-After`。
   全部 Key 无效时立即 429——等也没用。
7. 响应首字节转发后，流原样透传——不会在流中途切换 Key。

### 4.1 冷却时长解析链（被动，零探测）

429 时刻，该 Key 的恢复时间直接从已知数据算出，**不发任何探测请求**：

1. 上游 `Retry-After` 头（最权威）；
2. 该 Key 的 `cooldown_secs` 覆盖；
3. **窗口推算**：容量取**配置值**（Key 的 `seed_rpm` > 提供商 RPM/TPM 限额按
   Key 数平摊；未配置则不推算，落到下一级）——RPM 维度：窗口内第 (n−容量+1)
   旧的请求滑出 60s 窗口的时刻即恢复时刻；TPM 维度：token 累计腾出"下一个平均
   请求"空间的时刻；两者取大，×0.9 偏低偏置（低估代价只是一次 250ms 重试并自愈；
   高估会把 Key 关太久），钳制在 2~900 秒；
4. 全局默认（默认冷却时间，60 秒）。

冷却期过后，**第一个真实请求就是探针**：成功即恢复，429 则用更新的数据重新推算。

> 旧版的后台二分探测器和 `learned_cooldown` 字段已移除/弃用；旧配置里的
> learned 值不再被读取。

### 4.2 路由策略

策略层把整个池视作 `(provider, model, api_key_id)` 三元组表，每次请求：

1. **解析**请求模型 → `(provider, model)` + 模型组。裸模型名（无 `provider/`
   前缀、无别名）无法解析 provider，`lock_provider` 自动降级为关。
2. **过滤**——两个开关把全表缩成候选集：

   | `lock_model_group` | `lock_provider` | 候选集 |
   |---|---|---|
   | 开 | 开 | 精确 `(provider, model)`——只轮换 Key（默认） |
   | 开 | 关 | 该模型组跨所有提供商（模型优先） |
   | 关 | 开 | 解析出的 provider 的所有模型（提供商优先） |
   | 关 | 关 | 全表（可用优先） |

3. **排序**——比较器 = 固定前导 `有效 ↓` + `非冷却 ↓`（恒开）+ 用户 0–3 个
   排序键（A–K），末位游标轮转（轮询负载均衡）：

   | ID | 属性 | 方向 | ID | 属性 | 方向 |
   |---|---|---|---|---|---|
   | A | success_rate | ↓ | G | bill_balance | ↓ |
   | B | rpm | ↓ | H | bill_balance | ↑ |
   | C | tpm | ↓ | I | price | ↑ |
   | D | avg_tftt | ↑ | J | tps | ↓ |
   | E | token_balance | ↓ | K | availability | ↓ |
   | F | token_balance | ↑ | | | |

   `token_balance` / `bill_balance` 在 provider 不上报时取 `+∞`（`∞` 在 `↓`
   下排最前、在 `↑` 下排最后）。

   **K（availability，综合可用性）** = `平滑成功率 × 容量余量`。成功率按 5 分钟
   滚动窗口贝叶斯平滑 `(ok + 2) / (n + 2)`（无历史 → 1.0，不惩罚新 Key）。
   余量 = `1 − max(RPM利用率, TPM利用率)`，钳制 `[0.05, 1]`——接近上限的 Key
   被降权但永不排除（真限流交给冷却层）。**容量只来自配置**（`seed_rpm` >
   提供商限额平摊；都没有则中立，K 退化为只看成功率）——429 采样无法区分
   RPM/TPM 触发，已被证明不可用于容量测量。

4. **走表**——从上往下取第一个 `有效 + 非冷却` 行。
5. **终结**——全冷却 → 挂起等待（见 §4 第 6 条）；无有效行 / 候选集空 → 429。

### 4.3 每 Key 指标 seed（手动 seed + 自动覆盖）

全新 Key 没有实测指标，任何 B/C/D/J 排序都会把它排最后、永远轮不到。设置
**seed**（`seed_rpm` / `seed_tpm` / `seed_success_rate` / `seed_avg_tftt_ms` /
`seed_tps`）可让新 Key 立即参与排序；Key 一旦服务真实流量，实测值即接管。
Seed 目前通过配置文件或 `PUT /api/providers/{id}/keys/{key_id}` 设置
（字段传 null = 清除；不传则不改动）。

## 5. Anthropic 协议（Claude Code 接入）

网关同时暴露 **Anthropic Messages** 端点，Claude Code、Anthropic SDK 直接接入：

```
ANTHROPIC_BASE_URL=http://127.0.0.1:8000   ANTHROPIC_API_KEY=<网关key>  claude
```

- **鉴权**：`Authorization: Bearer <key>` 和 `x-api-key: <key>` 都接受。
- **提供商协议**：每个提供商可设 `protocol: "openai" | "anthropic"`（缺省 openai）。
  入站 OpenAI × 上游 Anthropic、入站 Anthropic × 上游 OpenAI 等任意组合都通——
  网关双向翻译（system、max_tokens、stop_sequences、tools/tool_choice、
  图片内容块、流式事件序列、stop_reason ↔ finish_reason）。
- **count_tokens**：Anthropic 上游透传真实端点；OpenAI 上游本地估算（约 4
  字符/Token），永远不返回 404。

## 6. 模型命名与别名

- **复合名**：`provider/model`（provider 匹配名称或 ID）。
- **别名**：自定义短名（如 `fast` → `gpt-4o-mini`），优先于复合名，全局唯一。

`GET /v1/models` 列出所有已启用托管模型及别名（含 `supports_images` 声明）。

## 7. 接入 Agent 与工具

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="anything")
```

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \

```

开启本地鉴权后 `api_key` 填网关鉴权 Key。流式与非流式均支持，逐字节透传。

## 8. 配置文件参考（`gateway.json`）

```json
{
  "api_port": 8000,
  "ui_port": 8001,
  "default_cooldown_secs": 60,
  "max_hold_secs": 120,
  "auth": { "enabled": false, "keys": [] },
  "strategy": {
    "filter": { "lock_model_group": true, "lock_provider": true },
    "sort": ["K"]
  },
  "model_groups": [
    { "id": "gpt-4o", "entries": [["openai", "gpt-4o"], ["azure", "gpt-4o"]] }
  ],
  "providers": [
    {
      "id": "p-xxx",
      "name": "openai",
      "base_url": "https://api.openai.com/v1",
      "protocol": "openai",
      "rpm_limit": null,
      "tpm_limit": null,
      "keys": [
        { "id": "k-xxx", "key": "sk-...", "display_name": "主力", "cooldown_secs": null,
          "seed_rpm": null, "seed_tpm": null, "seed_success_rate": null,
          "seed_avg_tftt_ms": null, "seed_tps": null }
      ],
      "models": [ { "id": "gpt-4o", "enabled": true, "context_length": 128000, "supports_images": true } ],
      "model_allowlist_only": false,
      "aliases": { "fast": "gpt-4o-mini" },
      "price_table": { "gpt-4o": 2.5 },
      "output_price_table": { "gpt-4o": 10.0 }
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `api_port` / `ui_port` | 本地 API 与控制台端口（重启生效） |
| `default_cooldown_secs` | 冷却链兜底（§4.1） |
| `max_hold_secs` | 全冷却挂起等待上限（默认 120） |
| `auth` | 本地 `/v1` API 的可选 Bearer 鉴权 |
| `keys[].display_name` | 显示名；空 = 显示掩码 Key。旧配置的 `label` 字段自动迁移 |
| `keys[].cooldown_secs` | 每 Key 冷却覆盖；`null` = 走冷却链下一级 |
| `keys[].seed_*` | 预置初始指标，Key 服务流量后自动被实测覆盖（§4.3） |
| `providers[].rpm_limit` / `tpm_limit` | 手动 RPM/TPM 上限；`null` = 无上限（控制台显示实测聚合） |
| `strategy.filter` / `strategy.sort` | 过滤开关 + 0–3 个 A–L 排序键（§4.2） |
| `model_groups` | 同一逻辑模型跨提供商 |
| `models[].context_length` / `supports_images` | 上下文窗口 / 图片输入能力声明 |
| `price_table` / `output_price_table` | 每模型输入/输出价格（¥/1M tokens，0 = 免费） |

统计（`stats` 字段）也合并在同一文件里，重启不丢；导入配置时统计被采纳。
控制台每次修改都会原子重写该文件。

## 9. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 明明有 Key 可用，客户端却收到 429 | 剩余 Key 全部在冷却且等待超过 max_hold_secs，或全部无效。看 API Key 页状态与最近错误 |
| 某 Key 显示无效 | 上游拒绝鉴权（401/403）或配额耗尽。修复 Key 后等 30 分钟隔离结束或点「解除」 |
| 计数器涨得快 | Agent 每次工具调用就是一次请求；全冷却挂起期间不产生新尝试 |
| 端口被占用 | 已有实例在运行（`taskkill //F //IM llm-gateway.exe`），或改端口 |
| 改了端口没生效 | 端口修改重启后生效 |
| 网页控制台空白 | 先硬刷新（Ctrl+F5）；仍空白看浏览器控制台报错 |

## 10. 管理 REST API（控制台所用）

均在 `http://127.0.0.1:8001`：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/status` | 完整快照：设置 + 每提供商的 Key（掩码、显示名、冷却/无效/请求数/指标） |
| `GET /api/stats` | 统计：总量、24h 直方图、按 Key/提供商/模型 |
| `GET/POST /api/providers` · `PUT/DELETE /api/providers/{id}` | 提供商增删改查 |
| `POST /api/providers/{id}/keys` | 添加 Key（`{key, display_name?}`） |
| `PUT /api/providers/{id}/keys/{key_id}` | 更新 Key 显示名 / Key 本体 / 指标 seed |
| `DELETE /api/providers/{id}/keys/{key_id}` | 删除 Key |
| `PUT /api/providers/{id}/rate-limits` | 提供商 RPM/TPM 限额（null = 清除） |
| `POST /api/strategy/dry-run` | 预览路由 |
| `DELETE /api/keys/{key_id}/cooldown` | 清除冷却或无效隔离 |
| `POST/PUT/DELETE /api/providers/{id}/models[...]` | 托管模型与属性 |
| `GET /api/providers/{id}/upstream-models` · `POST .../models/import` | 上游模型拉取与导入 |
