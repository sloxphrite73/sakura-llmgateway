# Sakura LLM Gateway — 使用说明

一个本地 LLM API 网关，位于你的 agent/工具与上游 OpenAI 兼容提供商之间。
它为每个提供商维护一个 API-Key 池，在某个 Key 被限流时自动切换到下一个，
并提供 Web 控制台管理一切。

> English: [USAGE.md](USAGE.md)

---

## 1. 安装与启动

### 一键脚本（推荐）

| 平台 | 步骤 |
|---|---|
| Windows | 先双击一次 `llm-gateway/install.bat`（自动安装 Rust、下载 MinGW、构建 release、生成 `gateway.json`）。之后每天用 `llm-gateway/start.bat` 启动即可。 |
| Linux / macOS / Git Bash | 先 `./install.sh` 一次，之后 `./start.sh`。 |

注意：

- `start.bat` / `start.sh` 是**前台运行**——使用期间窗口必须保持打开，关窗即停止网关。
- 如果 release 二进制已存在，启动脚本会跳过构建直接运行。

### 手动方式

```bash
cd llm-gateway
cargo build --release
./target/release/llm-gateway.exe --config gateway.json   # Windows
./target/release/llm-gateway --config gateway.json       # Linux/macOS
```

启动后：

| 服务 | 地址 |
|---|---|
| OpenAI 兼容 API | `http://127.0.0.1:8000/v1` |
| Anthropic Messages API | `http://127.0.0.1:8000/v1/messages`（Claude Code 等，见第 5 节） |
| Web 控制台 | `http://127.0.0.1:8001/` |

## 2. 安卓端（APK）

安卓版与 Windows 版是**同一个 Rust 网关**：CI 把它交叉编译出 `arm64-v8a` /
`armeabi-v7a` / `x86_64` 三种 ABI，打包进 universal APK，由一个前台服务启动并守护。

### 安装

1. 从 [GitHub Releases](https://github.com/sloxphrite73/sakura-llmgateway/releases)
   下载 `sakura-llmgateway-vX.Y.Z-universal.apk`（手机浏览器直接下载即可）。
2. 点击安装；如提示"禁止安装未知应用"，按提示允许该来源安装。
3. 打开 app，桌面图标即启动页同款樱花 🌸。

### 首次启动

- **导入 gateway.json**——从文件管理器选择电脑上导出的配置文件，验证通过即生效；
- **跳过，用空配置启动**——app 自动生成一份合法的空配置并直接启动网关，
  之后在控制台里添加提供商和 Key。

### 日常使用

| 事项 | 说明 |
|---|---|
| 前台服务 | 网关以常驻通知运行（"Sakura LLM Gateway 运行中"），点通知回到控制台；通知带"停止"按钮 |
| 通知权限 | Android 13+ 首次启动会弹出通知权限请求；拒绝后服务仍在运行，只是通知不可见，可在系统设置中补授（v0.3.1 加入） |
| 控制台 | app 内全屏 WebView，即 `http://127.0.0.1:8001/` 同一个页面；支持浏览器内的导入/导出、确认弹窗 |
| 接入地址 | 本机 agent/工具指向 `http://127.0.0.1:8000/v1` |
| 生命周期 | app 退到后台服务继续运行；系统杀掉后 START_STICKY 自动拉起；探活看门狗（首次 2 秒、之后每 10 秒）发现假死即自动重启网关 |
| App 内导入 | 控制台"导入配置"按钮直接调起系统文件选择器，导入即热生效 |
| 系统级导入 | 文件管理器中对 `gateway.json` 用"打开方式 → Sakura LLM Gateway"，网关运行中会热加载 |
| 导出 | 控制台"导出配置"调起系统"另存为"对话框 |

### 从电脑迁移配置到手机

1. **电脑**：控制台 → 配置页签 → **导出配置**，得到 `gateway.json`
   （含全部提供商、Key、模型、别名与学习到的冷却时间）。
2. **传输**：通过 USB、微信/QQ 文件传输助手、网盘等任意方式把 `gateway.json`
   发到手机（微信接收后建议"用其他应用打开 → 保存到文件"）。
3. **导入**（二选一）：
   - 首次启动直接选"导入 gateway.json"；
   - 已在运行：手机文件管理器找到该文件 → 打开方式 → **Sakura LLM Gateway**，
     配置立即热加载，无需重启。
4. **验证**：回到 app 控制台，状态页签应显示全部 Key 在线；用手机浏览器或
   本机 agent 调 `http://127.0.0.1:8000/v1/chat/completions` 验证一次。

> 提示：模拟器（MuMu / 雷电 / 夜神）同样可安装使用。遇到问题时请先升级到 **v0.3.2 及以上**（修复了启动竞态、通知权限请求、小屏设备引导页按钮过小），或下拉通知栏
> 点"停止"后重新打开 app。

## 3. Web 控制台

浏览器打开 `http://127.0.0.1:8001/`，从上到下：

### 全局设置

- **默认冷却时间（秒）**——上游没有返回 `Retry-After` 且 Key 没有单独覆盖时，429 的 Key 休息多久（默认 60）。
- **每请求最大尝试次数**——重试预算倍数（默认 3）。实际预算 = `max_attempts × Key 数量`，所以只有所有可用 Key 都试过之后，请求才会失败。
- **API 端口 / UI 端口**——重启后生效。
- **本地 API 鉴权**——默认关闭。开启后 agent 访问 `/v1/*` 必须携带配置的鉴权 Key 作为 Bearer token。

### 现有提供商（免费目录）

配置页顶部的「现有提供商」面板内置一批**免费/有免费额度的 OpenAI 兼容上游**
（SiliconFlow、Z.AI GLM、OpenRouter `:free`、Pollinations（免 Key）、Cerebras、
NVIDIA NIM、Groq、Mistral、Cloudflare Workers AI）：

- 每张卡片显示免费说明、预置免费模型列表（可展开）、**领额度教程**链接
  （指向本仓库 `doc/free-providers/` 的分步教程）与**注册/取 Key**链接。
- 添加：看教程领好 Key → 粘贴进卡片输入框（多个 Key 每行一个）→ 点**确认添加**。
  网关自动创建提供商 + 导入预置免费模型 + 写入 Key，一步完成。
- **Pollinations 免 Key** 可直接添加（不填 Key 也能用，匿名有限速）。
- 已添加过的卡片会标注「✓ 已添加 · N key」，可继续追加 Key。
- 点「从 GitHub 更新目录」可拉取最新目录（v0.3.3 加入；目录同时内嵌在二进制里，
  离线也能用）。

### 提供商

每个提供商卡片管理一个上游：

- **编辑 / 删除**提供商（名称 + baseURL）。
- **API Key**——添加/删除 Key、可选的每 Key 冷却时间覆盖、实时状态、请求数、最近错误。Key 值始终掩码显示。
- **模型**——托管模型目录（见第 4 节）。
- **别名**——映射到上游模型名的短名称（见第 5 节）。

**Key 状态含义：**

| 状态 | 含义 |
|---|---|
| 🟢 可用 | 健康，参与轮询 |
| 🟡 冷却 · 剩余 Xs | 暂时停用（429 或 5xx），倒计时到 0s 自动恢复 |
| 🔴 无效 · 剩余 Xs | 鉴权被拒（401/403）——重试不可能成功，因此隔离 30 分钟。修复 Key 后点**解除无效**立即恢复 |

### 主题与语言

- 页头右侧的 ☀️/🌙 按钮切换浅色/深色模式；旁边的「EN / 中」按钮切换英文/中文界面——覆盖全部文字（表格、按钮、弹窗、输入框提示）。两者都按浏览器记忆（localStorage）；语言默认跟随浏览器设置（v0.3.2 加入）。
- 页头顶部并列展示两个接入地址：`OpenAI 兼容接口 …/v1` 与 `Anthropic Messages …/v1/messages`，**点击即可复制**（v0.3.2 加入）。

## 4. Key 池行为（429 时发生了什么）

1. 请求按轮询方式分配到提供商的各个 Key。
2. 收到 **429** 的 Key 进入冷却：冷却时长优先级 = 上游 `Retry-After` 头 → `learned_cooldown`（二分探测学习所得，见下文第 4.1 节）→ 每 Key 覆盖 → 全局默认。网关等待 **1.5 秒**后在下一个 Key 上重试同一请求。

### 4.1 冷却学习（二分探测）

Key 被 429 后，后台探测器会自动测出它真实的限流窗口并写入 `learned_cooldown`（控制台和配置文件可见）：

1. **初值 T** = 上次学习值（没有则用全局默认），限制在 2–900 秒内。
2. **定界**：等待 T 秒后发一个微小探测请求（该提供商第一个启用的托管模型，`max_tokens: 1`）——成功说明窗口比 T 短，进入区间 `[T/2, T]`；仍 429 说明更长，进入 `[T, 2T]`（上限 900 秒）。
3. **二分**：对区间二分约 5 轮（中点探测，成功取上半、429 取下半），收敛到 ±1 秒。
4. **写入**：取区间**中点**作为 `learned_cooldown`（去抖动写入配置）。

边界保护：每测量最多 10 次探测；401/403/其他 4xx/网络错误视为"不可学习"直接放弃；每把 Key 至多每小时重新校准一次（`RELEARN_AFTER_SECS = 3600`）；每把 Key 同时只有一个探测器。
3. **401/403**（Key 无效）改为 30 分钟隔离——反复重试死 Key 只是浪费调用。
4. 其他 Key 级错误（408/5xx、网络错误）让 Key 停用 5 秒后轮换。
5. 请求级错误（如 **400** 坏请求体）直接返回客户端——换什么 Key 结果都一样。
6. 只有当**所有** Key 都在冷却/无效时，客户端才会收到 `429`（附停用 Key 列表，快速失败不等待）。
7. 响应首字节转发后，流原样透传——不会在流中途切换 Key（那会损坏输出）。
8. Agent 对话中的每次失败请求就是一次普通的 `/v1/chat/completions` 调用：一个客户端请求 → 每次尝试用一个 Key。

## 5. Anthropic 协议（Claude Code 接入）

网关同时暴露 **Anthropic Messages 协议**端点，Claude Code、Anthropic SDK 等
客户端可以直接接入，无需任何转换层：

```
ANTHROPIC_BASE_URL=http://127.0.0.1:8000   ANTHROPIC_API_KEY=<网关key>  claude
```

| 端点 | 说明 |
|------|------|
| `POST /v1/messages` | 对话（流式 + 非流式，tools / 图片内容块） |
| `POST /v1/messages/count_tokens` | Token 计数 |

- **鉴权**：`Authorization: Bearer <key>` 和 `x-api-key: <key>` 都接受；
  `anthropic-version` 头直接忽略。
- **提供商协议**：每个提供商可设置 `protocol` 字段（控制台添加提供商时的下拉框，
  或配置文件中 `"protocol": "openai" | "anthropic"`，缺省 openai）：
  - `openai` —— 上游是 OpenAI 兼容 API（sensenova、openai 等），
    `/v1/messages` 进来的请求会被翻译成 OpenAI 格式发出，响应/流再翻译回来；
  - `anthropic` —— 上游本身是 Anthropic 兼容 API（如 api.anthropic.com），
    请求以 `x-api-key` + `anthropic-version` 头发往 `{base_url}/v1/messages`。
- **完整矩阵**：两个入站端点（`/v1/chat/completions`、`/v1/messages`）
  × 两种上游协议，任意组合都通——OpenAI 客户端同样能用真 Claude API 的 Key 池。
- **翻译覆盖**：system 顶层字段、max_tokens（Anthropic 必填）、stop_sequences、
  tools/tool_choice（function ↔ tool_use 双向映射）、图片内容块（base64/URL）、
  流式事件序列（message_start → content_block_delta… → message_stop ↔
  OpenAI data: chunk）、stop_reason ↔ finish_reason。
- **count_tokens**：Anthropic 协议上游透传到上游真实端点；OpenAI 上游没有等价
  端点，网关本地估算（约 4 字符/Token），永远不返回 404。
- Key 池、冷却、二分探测学习、统计对 Anthropic 上游同样生效（探测请求体会按
  上游协议构造）。

## 6. 模型管理

每个提供商的**模型**区块管理一个模型目录，每个条目为 `{ id, enabled }`：

- **手动添加**——输入上游模型 ID（如 `gpt-4o`）。
- **从上游拉取**——调用提供商的实时 `/v1/models`，弹出勾选列表（已添加的模型不勾选），选择后导入。
- **启用/禁用**——不删除即可临时下线某个模型（比如配额耗尽）。
- **白名单模式**（仅允许列表内模型，默认关）：
  - 关 + 列表为空 → 未托管，所有模型放行（向后兼容）；
  - 开 → 只允许请求列表内已启用的模型，其余返回明确的 404。
- 被禁用的模型和悬空别名不会出现在 `/v1/models` 中。

---

## 7. 模型命名与别名

Agent 请求模型的方式：

- **复合名：**`provider/model`——如 `openai/gpt-4o`（`provider` 匹配提供商的名称或 ID）。
- **别名：**你定义的任意短名，如 `fast` → `gpt-4o-mini`。别名优先于复合名，跨提供商全局唯一。

`GET /v1/models` 列出所有已启用的托管模型（`provider/model` 格式）及全部有效别名。

## 8. 接入 Agent 与工具

任何支持 OpenAI 接口的客户端都能用：

```python
from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="anything")
```

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-4o","messages":[{"role":"user","content":"hi"}],"stream":true}'
```

如果开启了本地 API 鉴权，`api_key` 填网关的某个鉴权 Key（Bearer token）。

流式（SSE）与非流式响应均支持，逐字节透传。

## 9. 配置文件参考（`gateway.json`）

```json
{
  "api_port": 8000,
  "ui_port": 8001,
  "default_cooldown_secs": 60,
  "max_attempts": 3,
  "auth": { "enabled": false, "keys": [] },
  "providers": [
    {
      "id": "p-xxx",
      "name": "openai",
      "base_url": "https://api.openai.com/v1",
      "protocol": "openai",
      "keys": [
        { "id": "k-xxx", "key": "sk-...", "label": "main", "cooldown_secs": null }
      ],
      "models": [ { "id": "gpt-4o", "enabled": true } ],
      "model_allowlist_only": false,
      "aliases": { "fast": "gpt-4o-mini" }
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `api_port` / `ui_port` | 本地 API 与控制台端口（重启生效） |
| `default_cooldown_secs` | 无 `Retry-After` 且无每 Key 覆盖时的 429 冷却时长 |
| `max_attempts` | 重试预算倍数（实际预算 = × Key 数量） |
| `auth` | 本地 `/v1` API 的可选 Bearer 鉴权 |
| `keys[].cooldown_secs` | 每 Key 冷却覆盖；`null` = 用全局默认 |
| `models` | 托管目录；为空 = 未托管 |
| `model_allowlist_only` | 拒绝不在（非空）列表内的模型 |
| `aliases` | 客户端可见名称 → 上游模型名 |
| `providers[].protocol` | 上游协议：`openai`（默认）或 `anthropic`，见第 5 节（v0.3.0 加入） |

每次在控制台修改都会原子重写该文件。网关运行时手动编辑也可以——但控制台的修改会覆盖手动修改。

> **警告：** 某些工作副本中的 `llm-gateway/test/gateway.json` 含有本地测试用真实 API Key——切勿提交或外传。

## 11. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 明明有 Key 可用，客户端却收到 429 | 剩余 Key 全部在冷却/无效中；鼠标悬停 Key 状态看最近错误。修复或解除无效 Key。 |
| 某 Key 显示 无效 | 上游拒绝了鉴权（401/403）——Key 被吊销、写错或配额等级不足。修复后点解除无效。 |
| 真实请求不多，计数器却涨得快 | Agent 每次工具调用就是一次 API 请求，每次 429 重试也按次计数。401 隔离 + 429 退避（v0.2 加入）已把浪费压到最低，死 Key 现在每 30 分钟最多消耗 1 次调用。 |
| `cargo run` 询问运行哪个二进制 | 用 `cargo run --bin llm-gateway`，或直接运行编译产物 / 启动脚本。 |
| 端口被占用 | 已有网关实例在运行（Windows 用 `taskkill //F //IM llm-gateway.exe`），或修改 `api_port`/`ui_port`。 |
| 改了端口没生效 | 端口修改重启后生效。 |
| `.bat` 窗口一闪而过 | 重新下载修复后的脚本（纯 ASCII 版本）；在已打开的 cmd 窗口中运行可以看到报错。 |

## 12. 管理 REST API（控制台所用）

均在 `http://127.0.0.1:8001`：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/status` | 完整快照：设置 + 每提供商的 Key（掩码）及冷却/无效/请求数/最近错误 |
| `GET/POST /api/providers` | 列出 / 创建提供商 |
| `PUT/DELETE /api/providers/{id}` | 更新 / 删除提供商 |
| `POST /api/providers/{id}/keys` · `DELETE /api/providers/{id}/keys/{key_id}` | 添加 / 删除 Key |
| `DELETE /api/keys/{key_id}/cooldown` | 清除 Key 的冷却**或**无效隔离 |
| `POST /api/providers/{id}/models` · `DELETE .../models/{model_id}` · `PUT .../models/{model_id}` | 添加 / 删除 / 启停托管模型 |
| `GET /api/providers/{id}/upstream-models` | 拉取提供商实时 `/v1/models` |
| `POST /api/providers/{id}/models/import` | 批量导入 `{ "models": ["a", "b"] }` |
| `POST /api/providers/{id}/aliases` · `DELETE .../aliases/{alias}` | 设置 / 删除别名 |
| `PUT /api/settings` | 更新全局设置 |
